## 2. 用户原意与最近反馈

### 最初需求

1. **登录**：登录卡片过于普通、视觉不对称；卡片外背景希望有代码／数据动态表现，极客感，可做伪 3D 旋转。
2. **侧栏**：原版太密集、文字层级不清、SVG 与 UI 不协调、分类不清楚。
3. **文案**：说明太多、不简洁；页面应突出用户当前在做的事，不要大段介绍功能。
4. **渠道模型**：默认自动向上游发现所有模型，持续跟踪变化，但控制资源和请求占用。
5. **Magpie**：相关接入、账号、监控体验参考 Magpie 原本做法；功能要跟随上游演进，网关也要更新。
6. **凭据导入**：该页不要；之后用户明确，不只是删页面，是能力全部取消。
7. **模型总览**：目前混乱；自动同步价格、思考能力、上下文信息，参考 models.dev 和 OpenRouter，允许模糊匹配；相关元数据要向后续接口暴露。
8. **RTK**：属于网关内化功能；默认全开，只有全局开／关，不要独立一级页面。
9. **用量**：旧 Console 热力图比当前新组件版好，希望融合旧版优点和新组件；图表要回答用户关心的问题。统计、图表、请求明细、缓存需要协调而非四个割裂页面。
10. **账号监控**：对齐 Magpie，同时保留以前可重置账号的支持。
11. **沟通方式**：只问少数关键问题；可查事实由代理自己调查。

## 7. 必须在实施前处理的风险

### 7.1 真实 OAuth 缺口不是换皮问题

[verified · 源码] `server/magpieOAuth.ts:154-207` 的 `submitLocalOAuthCallback` 把回调 code 或随机值当 `access_token`，随机生成 refresh token 和 `@oauth.crosery.local` 邮箱，再保存并标记成功；未见真实供应商 token exchange。

这条代码路径不能作为真实授权成功的实现。下一阶段应核对运行时入口并接通原生真实授权，不得在新 UI 里把它包装成“已对齐 Magpie”。**本轮没有执行这条路径，也未新建或修改凭据。**

### 7.2 模型同步重复联网

[verified · 源码] `server/modelSync.ts:96-110,172-193,314-347` 自己请求渠道模型目录，并被文件事件与 5 分钟定时器触发。`env:`／`cpa:` key 被排除后仍可能走匿名探测。

同时存在共享 `~/.agents/crosery/sync.mjs` 采集链。统一职责、缓存、冷却、锁是任务本体，不能只把周期调大。

### 7.3 自动发现不等于正确可用性

目录存在、人工启用、账号有额度、最近推理成功是不同维度。元数据模糊匹配也不能决定路由／访问权限。不要把一条失败全局传播为“模型不可用”。

### 7.4 更新发现不等于升级完成

候选检测、构建脚本、实际内核构建、文件替换、服务激活和健康检查并不天然是一条完整链。此前只读调查发现 `scripts/magpie-update.mjs` 与真实内核构建脚本之间需进一步核对；未运行验证，不得引用为升级可用证明。

### 7.5 特有能力不能在“对齐上游”时丢失

Claude Banked Reset 是 Console 特有支持；调查的 Magpie 版本没有等价实现。保留 Codex Reset Credits、Claude Banked Reset、`cooldownCleared` 部分成功，以及 Key 权限／额度／分组并发。
