# Crosery API Console 重设计 Spec

Crosery: **目标是完整、易扫读、对齐 Magpie 交互的网关工作台，不是更空的极简后台。**

状态：需求规格／待设计评审。不是已经获批的最终 UI 或已落地的后端架构。

相关交接：[console-redesign-handoff.md](console-redesign-handoff.md)。本文件只规定本轮相关行为；不授权部署、真实账号操作或无关重构。

## 1. 标记与优先级

- **[需求]**：用户明确提出，不能擅自缩减。
- **[约束]**：为满足正确性、安全、既有能力保留而设的实施边界。
- **[提案]**：代理建议，需通过草图或关键决策确认，不是用户已批准的细节。
- **[待定]**：影响产品或运行风险、仍需收敛的决定。
- MUST / SHOULD：必须／推荐；但不能把标为提案的参数解释成已确认值。

最新反馈要求保留当前分类方向，重新处理表现、信息完整度、Magpie 对齐和空间利用。第一轮配色、留白、卡片尺度、表格字段以及 mock 数量均无继承义务。

## 2. 范围与非目标

### 范围

- 登录、应用壳、导航、概览、API Key、渠道／账号／授权／额度、模型、用量四视图、设置、更新状态、帮助。
- 模型自动发现、增删状态、可用性、价格／上下文／思考信息更新与 API 暴露。
- 统一现有更新机制，降低重复请求、资源竞争与账号风险。
- Magpie 原生真实能力适配，保留 Console 额度、访问控制、重置与分析优势。
- 凭据导入能力完整下线、RTK 内化为网关全局策略。

### 非目标

- 不重选前端栈、不引入无必要组件库、不默认迁移所有历史数据。
- 不照搬 Magpie 所有产品模块（如与本任务无关的 library/plugins/sessions）。
- 不自动删除已有账号或 OAuth 凭据；取消导入不等于取消运行时凭据存储。
- 不未经授权升级生产、切换流量、登录真实供应商或消耗重置额度。
- 不承诺“不封号”；只实现可核验的请求控制与风险提示。

## 3. 体验目标与可观察结果

| ID | 目标 | 可观察验收 |
|---|---|---|
| UX-01 | 一眼知道当前任务 | 页面标题、筛选、主操作与结果区有明确层级；无大段功能介绍占据首屏 |
| UX-02 | 适中但完整的信息密度 | 1097×935 下主要工具栏和首批可操作记录可见；不以大卡片只装一个数值；1440px 不留下无用途的大片空区 |
| UX-03 | 保留可读性 | 不靠全站缩字号／缩点击区解决空白；正文、辅助文本、数值、ID 有稳定角色；图标视重一致 |
| UX-04 | 行为对齐 Magpie | 授权在服务／账号上下文完成；首选、暂停、额度、恢复、重置结果具有原生语义，不能只有原生图标 |
| UX-05 | 跨视图不丢上下文 | 日期、Key、模型、渠道及有关筛选保留；从图表／排行到请求明细不重新设置 |
| UX-06 | 有效使用空间 | 横向空间优先用于同任务的比较、列表详情、分布和证据，不添加装饰性指标充数 |

## 4. 信息架构与路由

[提案／方向暂可沿用]

```text
概览
API Key
渠道与账号：渠道 / 账号 / 额度与健康
模型
用量：总览 / 请求 / 缓存 / 性能与错误
设置：网关策略 / 更新状态
接入帮助
```

- [需求] RTK、凭据导入不再独立占一级导航。
- [待定] 账号授权是否保留独立导航，还是保留显著的工作区入口＋原生就地流程。用户要求看图后判断；不得再次用纯文字替用户定案。
- [约束] 功能被合并时，迁移菜单、路由、面包屑、跳转和消费者；处理已有深链，不留无法到达的旧页面或导航死项。是否保留兼容重定向按项目切换规范处理，不长期维护双套实现。
- [约束] `server/navRoutes.test.ts` 对导航／路由一致性有约束，实施时更新真实行为契约，不只删测试以绕过。

## 5. 视觉和布局规范

### 5.1 应用壳

- [需求] 分组清楚、选中项明显、图标与文字对齐，减少过密侧栏。
- [约束] 左栏按工作区固定视口高度；长内容滚动不把设置、账号信息推到文档底部。可滚动导航与主内容分离。
- [提案] 桌面侧栏约 200–224px、主内容边距 24px 起步、主要区块间距 16–24px。只是起点，以真实内容验证，不要求逐像素复用。
- [约束] 减少多层“页面标题＋说明＋工具条＋重复标题＋卡片标题”；说明只留必要范围、风险和错误。
- [约束] 工作区宽度服务于内容。数据列表可满宽；需要说明时用关联详情区，不在只有三行内容的页尾留下大片空白。

### 5.2 Magpie 对齐方式

MUST 同时核对：

1. **对象**：服务、渠道、账号、窗口、模型、请求的关系。
2. **动作**：使用、设为首选、暂停、恢复、重新授权、移除、重置。
3. **状态**：当前／临时首选、额度耗尽、恢复后切回、查询陈旧、推理冷却、失效。
4. **呈现**：服务 logo、行式列表、内嵌面板、小型额度环／条、紧凑选择控件。

不必照搬桌面应用整套尺寸；不允许只复制两个环形图就宣称对齐。

### 5.3 响应式与无障碍

- [约束] 在 1097×935（用户反馈视口）、1440px、390px 实际查看；窄至 320px 保留基本操作。
- [约束] 页面不得横向溢出；大表格可在明确局部容器横向滚动，关键名称、状态和动作保持可达。
- [约束] 弹层、菜单、表单、错误态、长名称、中文、键盘焦点均需验证。
- [约束] 颜色不是状态的唯一信息；减少动态效果时停用非必要动画。

## 6. 页面功能规格

### 6.1 登录：LOGIN

- [需求] 对称、平衡的账号／密码／按钮布局；修复普通默认卡片感，不恢复冗长介绍。
- [需求] 背景有代码和数据的伪 3D 旋转表现。
- [约束] 装饰数据不能来自真实请求、账号或密钥；动画不阻挡登录，不抢夺表单焦点，不持续进行网络请求。
- [约束] 页面不可见时暂停；遵守 reduced-motion，提供静态降级；不把沉重 3D 引擎作为默认方案。
- [约束] 保留错误、提交中、键盘提交、密码管理器语义，避免假安全声明。

### 6.2 概览：OVERVIEW

- [需求] 突出当前运行情况和需要处理的事项。
- [提案] 核心用量／费用／成功率／延迟＋趋势、近期异常、渠道或账号状态摘要；布局优先让用户看清问题及进入处理。
- [约束] 指标必须来自对应事实；不能根据一次 Console API 成功便写死“网关健康”。
- [约束] 概览不是用量页面复制品。简要摘要可跳入带上下文的详细工作区。
- [约束] 不用超大四张 KPI 卡和几行假数据填首屏；真实信息不足时如实空态，不伪造数据。

### 6.3 API Key：KEYS

保留并正确呈现已有能力，不因重设计静默丢失：

- 创建、编辑、一次性安全查看／复制、启用／停用、删除。
- 日、周、累计总额度及相应重置；超额停用的恢复规则。
- 渠道／模型授权、全局并发、分组并发；值为 0 的含义以现有契约为准。
- 搜索、状态筛选、最近使用与使用明细入口。

[约束] 列表摘要和详情／编辑各有分工；不常驻明文 Key。重置／删除要明确目标和后果，不以“保存”模糊代替。

### 6.4 渠道与模型发现：CHANNELS

- [需求] 接入后默认自动发现该上游的模型，不要求用户反复手动拉取。
- [需求] 跟随新增、删除、不可用和恢复变化，控制占用。
- [约束] 列表展示渠道、协议、启用状态、模型数、近期结果、同步时间及可操作状态。不要把全部模型标签铺进每一行。
- [约束] 服务／账号相关明细可以展开或在关联面板查看，不把关键动作藏到无说明菜单。
- [约束] 自动发现不授予超出 Key ACL 的访问；人工停用模型／渠道不得被同步恢复。
- [约束] 同一模型在不同渠道上的状态独立；目录重复模型映射应按真实渠道归属。
- [约束] 不把共享 catalog 的全部模型无差别灌进第一个启用渠道。
- [约束] 支持不完整、错误、限流、无鉴权能力和不支持发现等状态；不以空数组冒充成功。

### 6.5 账号、授权与监控：ACCOUNTS

**对齐对象与动作，不只对齐视觉。**

- [需求] 按服务组织账号，授权和账号池的关系直观；参考 Magpie 原生流程。
- [约束] 展示身份、套餐、参与路由／暂停、首选、额度窗口及最近状态。原生的“当前 CLI 登录”和“网关参与路由”可能不同，不合成一个布尔值。
- [约束] 在实际支持时提供使用／首选、暂停／恢复、重新授权、移除；不可用能力必须说明原因，不能放会假成功的按钮。
- [约束] 暂停网关使用不等于退出 CLI；移除本地保存登录不等于删除供应商账号。用户应能理解实际影响范围。
- [需求] 保留 Antigravity 等分模型族额度信息；家族汇总应表示最受限窗口，不拿平均值掩盖受限。
- [需求] 保留 Claude Banked Reset、Codex Reset Credits、可用次数和到期时间；保留相关 Key 消耗占比。
- [约束] 额度环／条采用紧凑但可读布局；账号多时优先分组列表和概要，避免每个账号占半屏。

#### 授权状态机

```text
选择服务
  → 必要的风险／站点／方式确认
  → 启动（依赖未满足则明确提示）
  → 等待浏览器或设备码确认／必要时回填
  → 服务端真实验证成功 → 账号就地出现
  ↘ 失败／取消／过期 → 停止该流程，可明确重新发起
```

- [约束] provider 列表按当前已验证的 Magpie 能力，不照搬旧 CPA 固定八卡片。
- [约束] 风险、依赖安装、权限授权等需用户明确确认，不由后台自动接受。
- [约束] 同一 provider／账号授权流程去重，完成／取消／失败／到期后停止检查；设备码遵守服务端 interval 和 slow_down。
- [约束] 不能把 authorization code 当 access token，不能随机生成凭据并报成功。
- [约束] 取消凭据文件导入，不取消官方 OAuth 回调和设备码；API Key 渠道接入也不在删除范围内。

#### 额度重置结果

MUST 区分：成功、无可重置窗口、无次数、已兑换、冷却、不适用、不可用、**重置成功但本地推理冷却未清除**。

- 使用最早到期的可用次数，遵守后端幂等；未知结果不能盲目重复消耗。
- 重置前说明账号、次数、到期和不可撤销后果；没有用量时避免无意义消费。
- 重置完成后额度缓存与推理状态分别更新；不得用一次清冷却失败抹掉真实重置成功。
- [待定] Magpie Codex 原生 Auto-use 是否纳入。用户只要求保留可重置支持，未授权自动消耗；默认不新增自动兑换。

### 6.6 凭据导入下线：IMPORT-REMOVE

[需求，已确认] **全部取消**。

实施时：

1. 删除 `CredentialUploadPage`、导航、路由、页面跳转、上传按钮及 API 客户端。
2. 下线仅供该能力使用的上传 API 和处理链，更新调用者、帮助及契约测试。先查引用，不能凭文件名批量删。
3. 确认无 JSON／ZIP 导入、隐藏菜单、替代上传入口残留。
4. 不删除已保存账号、OAuth 运行时凭据、账号启停／代理／删除 API；这些不是文件导入能力。
5. 不把本次需求当作不可逆清理真实文件的授权。

### 6.7 模型：MODELS

- [需求] 搜索、对比模型与来源；自动同步价格、思考与上下文，允许合理模糊匹配。
- [约束] 列表至少能辨认：公开 ID／名称、渠道来源、实际可用性证据、上下文／输出上限、思考能力、参考价格、匹配来源、更新时间。
- [约束] 高密度信息可分主列／扩展行／详情，不用整页长文案或无穷标签；多渠道同名模型可展开比较。
- [约束] 价格未知是未知，不是 0；思考未知不是不支持；未测试不是不可用。
- [约束] 元数据匹配不改变真实路由 ID、权限、模型选择或计费源优先级。
- [提案] 优先精确 ID／明确别名，再在同提供商、家族、版本语义和能力边界内做唯一近似匹配；冲突就显示待定，不跨 pro/preview/不同规格借价格。
- [待定] models.dev 和 OpenRouter 冲突时的定价优先规则需依据既有计价实现和数据性质收敛，不能悄悄选择较低报价。

#### 模型与可用性语义

| 维度 | 必须保留的语义 |
|---|---|
| 目录状态 | 已发现、疑似下架、已确认下架；失败／部分响应不是下架 |
| 用户策略 | 人工启用／停用，优先于自动发现 |
| 运行证据 | 近期成功、限流／额度冷却、授权失效、明确不支持、未知／陈旧 |
| 作用范围 | provider、渠道、账号、模型及时间；不把局部故障误扩成全局 |
| 来源 | 获取时间、来源、是否近似匹配、缺失字段 |

[约束] 状态过期后降为未知或陈旧，不能无限保持“可用”。恢复优先根据真实调用或明确供应商状态；不要默认逐模型收费推理探活。

### 6.8 用量与分析：USAGE

[需求] 统计、图表、请求明细和缓存协调，优先回答用户问题，不以技术端点拆 UI。

[提案] 四个工作视图：总览／请求／缓存／性能与错误，共用筛选。默认费用还是运行优先仍待看图确认。

MUST 保留以下信息，不能为了简洁删除：

| 分区 | 用户问题与数据 |
|---|---|
| 总览 | 花了多少、用了多少、何时高峰、谁在消耗；请求、Token、估算成本、活跃天、模型／渠道／Key／客户端分布 |
| 热力图 | 日期、请求、成本、失败、新输入／输出／缓存读／缓存写、Top3 模型；色阶图例、空白日、键盘与悬浮／点击详情 |
| 请求 | 时间、模型、Key、渠道、客户端、状态、耗时、首字、Token 构成、思考等级、请求 ID／上游 ID、可用错误内容；敏感字段按权限处理 |
| 缓存 | 读取、写入、可比输入、命中口径、估算净节省、时间趋势、每请求明细；缺字段明确不可计算 |
| 性能与错误 | 成功率、首字与总耗时区分、平均／P95、错误分类、渠道对比；样本少和数据缺失明确展示 |

- [约束] 旧热力图优势与新组件交互结合，不缩成装饰小卡片。
- [约束] 热力图／排行／错误类别点选后携带相应筛选；返回、刷新、深链保留可理解状态。
- [约束] 各视图使用一致时间范围、时区、Key／模型／渠道／客户端含义；首字延迟不冒充总耗时。
- [约束] 实时流与历史明细协同；暂停观察、断线和恢复明确，不重复累计费用，缓冲区有上限。
- [约束] 成本注明估算、价格来源和未定价覆盖；缓存节省扣除写入成本，不因字段缺失强行补 0。
- [约束] 有用的细节放展开区或表格列配置，不复制第一轮“只剩几项数字”的简化。

### 6.9 RTK：RTK

- [需求] 网关内化能力、默认全部开启、仅全局开／关，不独立页面，不让用户分别配置一堆 agent。
- [约束] 开关要作用于真实网关路径，不能只修改本机 CLI 配置并宣称整个网关开启。
- [约束] 明确支持范围、失败和生效状态；不支持的路径不能伪报已优化。
- [约束] 切换后验证实际请求处理，保留关闭回退；不要把压缩／改写策略扩展到本任务未要求的内容。

### 6.10 设置与帮助

- [需求] 设置承载低频全局策略和更新状态；帮助保留接入所需信息。
- [约束] 正常页面不常驻整张技术调度表。用户先看到任务结果、陈旧／冷却／待处理；高级策略和记录可展开。
- [约束] 使用真实已验证的 endpoint／协议；代码示例不含真实密钥，不把草图接口字段当最终契约。

## 7. 所有自动更新的协调规格：SYNC

### 7.1 核心不变量

- **SYNC-01 唯一所有者**：每个外部资源只有一个负责联网／刷新者。Console、共享脚本、Magpie、原生 CLI 不重复维护同一份 Token 或模型请求。
- **SYNC-02 全局预算**：按主机／provider／账号／端点分层限流，跨调用者去重；手动刷新、多标签页、文件事件和重启不能绕过。
- **SYNC-03 单次执行**：同一任务跨进程互斥，锁有崩溃恢复；队列有界。需要强一致的激活步骤防止过期执行者覆盖新快照。
- **SYNC-04 有效快照**：成功校验后原子发布版本化数据；失败保留上次有效值并标记陈旧。不得因部分来源失败覆盖其他来源好数据。
- **SYNC-05 控制放大**：本地 SSE／报表／秒级计量不转化为逐页上游轮询；共享缓存读取不触发外部风暴。
- **SYNC-06 失效关闭**：401／403／风控／额度／429 依据具体信号处理，不能通过切号、换 IP、重新启动来绕过。
- **SYNC-07 资源有界**：超时、并发、响应体／目录规模、历史候选保留、重试次数、退避和队列都有边界；避免永久后台 CPU／I/O 消耗。
- **SYNC-08 人工策略优先**：发现与同步不覆盖手工停用、Key ACL、版本固定或明确暂停。

### 7.2 任务归属与触发

| 任务 | 触发原则 | 必须避免 |
|---|---|---|
| 渠道模型目录 | 接入后、缓存过期、合并后的用户需求；尊重渠道能力与提供商规则 | 每个页面、文件事件和手动按钮分别联网；无有效鉴权仍盲探 |
| 模型价格／上下文／思考 | 公共源共享缓存、条件请求、独立较低频率 | 每账号重复获取相同公共目录 |
| 模型可用性 | 真实请求结果、明确 provider 状态，按范围记录 | 全量逐模型付费探活；一次 429 判模型永久下线 |
| 额度与重置详情 | 使用活跃性、支持路径、有效 TTL；详细信息展开时可合并申请 | 所有账号无差别持续扫描；将额度接口限流等同推理封禁 |
| Token 刷新 | 原生凭证拥有者在临近到期时刷新 | Console 和 Magpie 并发刷新同一 refresh token |
| OAuth 状态 | 用户发起的有限生命周期；按 provider 间隔 | 无会话轮询、取消后继续、重复启动同 provider 流程 |
| 网关／RTK／CLI 更新 | 版本检测和候选准备独立；兼容验证后才可能激活 | 多个自更新器互相覆盖、检测即安装、跟随 main 即可运行 |
| 用量／报表／SSE | 本地采集与事件分发，共享存储／快照 | 破坏性消费队列被多处同时消费；实时与落库双计费 |
| 凭据同步遗留任务 | 先盘点真实所有者和迁移范围，再去重 | 取消文件导入时顺手删除运行时凭据同步或现存账号 |

[待定] 具体周期与全局并发值需结合实际部署、账号数、供应商限额和原生行为确定。第一轮示意数值不是批准参数。

### 7.3 限流和失败

- 429：解析秒数或 HTTP 日期形式的 Retry-After；以 provider 指定范围暂停。无 header 时使用有上限退避与抖动，不高频固定间隔重试。
- 401／invalid_grant：由唯一凭证拥有者执行受控刷新；无效或失败停止循环并要求重新授权。
- 403／风控挑战：暂停相关任务并展示恢复方式；不得自动绕过供应商安全检查。
- 5xx／超时：有限重试、退避；保留旧快照，断路后可控恢复。
- 凭据或公开源缺少权限：明确错误；不切成匿名抓取后把失败吞掉。
- 冷却持久化；应用启动不能把限流计数清空后突发重试所有任务。
- 低优先级目录／价格任务不得挤占正在进行的用户推理；需要的凭证刷新也不突破供应商限制。

### 7.4 网关升级生命周期

```text
发现候选 → 校验来源与固定版本 → 准备构建／制品
  → 离线契约与兼容检查 → 候选就绪
  → 满足获批激活策略／维护窗口
  → 暂停冲突变更 + 排空请求（有截止，超时延后）
  → 原子激活 → 健康与协议检查
  → 成功恢复调度 / 失败回到上一有效版本
```

- [需求] 自动跟随上游，但必须协调更新链路与账号安全。
- [待定] 正式 release／commit 来源、自动激活条件、维护窗口、允许中断；用户未选择此前 A/B/C。
- [约束] 真实 OAuth、额度重置、付费推理不作为未授权后台升级测试。
- [约束] 二进制回退不等于数据库／凭据变更可逆；有破坏性迁移时停止并单独处理。
- [约束] 新旧进程不能同时消费同一个用量队列或刷新同一凭证。
- [约束] 失败候选有记忆，不每个调度周期反复安装；保留运行、候选、失败原因和下次尝试信息。

## 8. API 与数据契约要求

**先检查既有消费者和上游契约，不先规定另一套 API。**

### 8.1 模型元数据

[需求] 后续接口能够获取价格、思考、上下文。

[提案] 可沿现有模型列表向后兼容添加元数据，或提供有明确权限的专门元数据端点。具体路径及字段名待检查调用者后选定；第一轮 `/v1/models` 示例不是已批准接口。

至少表达：

- 稳定路由模型 ID；显示名与 provider。
- context limit、output limit、reasoning 支持及可知等级；未知可显式表达。
- 价格单位、币种、input/output/cache read/cache write、必要 tier、来源与参考性质。
- 精确／别名／近似匹配、规范源 ID、来源更新时间、数据陈旧性。
- 若暴露可用性：只聚合调用方有权限访问的来源，不泄露其他 Key／账号／渠道身份。

近似匹配或参考价不得不经审查直接替换权威账单／用户自定义计价。

### 8.2 更新状态

管理 API 应能表达任务类型、作用范围、最近成功、当前状态、下次可执行、冷却原因、候选版本、运行版本及快照版本。不向普通模型客户端暴露凭据、私有 provider 地址或后台错误原文中的秘密。

### 8.3 报表与事件

- 同一筛选跨接口使用一致含义；结果带生成时间／陈旧状态。
- 请求事件去重，实时、历史、费用汇总保持同一记录口径。
- 已有请求明细隐私边界保持；不因新面板增加完整提示词／回复日志采集。
