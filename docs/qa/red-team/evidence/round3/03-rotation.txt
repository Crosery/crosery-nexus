# 主张4：备份轮转 —— 已验证基本语义；⚠️ 发现「并发/批量下最近操作的 backupId 会被轮转删掉」

探测器：`evidence/round3/probe-rotation.mjs`（我写的，独立于蓝队测试）
实例：F1=8808（RTK_BACKUP_KEEP=1）、F2=8809（KEEP=2）、G=8810（KEEP=10 默认），
三者各自 `RTK_BACKUP_DIR` 隔离，避免互相轮转干扰。

## 4.1 顺序操作：轮转生效，最新一份保留，rollback 可用 —— 已验证

```
F1 (keep=1) 顺序 3 次：
  dirs 每次都是 1 个；最新 id 始终存在；status.backups = [{"id":...,"at":...,"fileCount":29}]
  POST /api/rtk/rollback → 200 {"ok":true,"backupId":"2026-10-01T01-23-30-266Z","restored":29}
F2 (keep=2) 顺序 4 次：dirs 始终 ≤2，每次响应里的 backupId 都还在
```

## 4.2 响应瘦身 —— 已验证

```
toggle 响应字段：backup(路径) / backupId / backupFileCount / backupKeep，**无 backups[] 历史清单**（hasBackupsArray=false）
status.backups 现在只有摘要：[{"id","at","fileCount"}]（不再带 files[] 全量清单）
```

## 4.3 ⚠️ 必查项：轮转会删掉「本次刚创建、并且已经写进响应」的备份

F1（keep=1）2 个并发（不同 agent，两个请求都成功）：

```
round1: codex  200 ok=true backupId=2026-10-01T01-23-43-432Z
        claude 200 ok=true backupId=2026-10-01T01-23-43-435Z
        dirs 只剩 ["...435Z"]        ← codex 那份已被 claude 请求的轮转删掉
        referenced-but-missing: ["...432Z"]
round2: 同样复现（454Z 被删，只剩 457Z）
```

F2（keep=2）6 个并发：4 个已返回 200 的 backupId 在同一批里就被删掉（两轮均复现）。

**默认 keep=10 同样会中招**：G（8810）12 个并发不同 agent 的 ON，全部 200，但最早的两个 backupId
（…969Z、…975Z）在批次返回时已不在磁盘上（dirs 恰好剩 10 个）。两轮均复现。

含义：`/api/rtk/toggle` 返回的 `backupId` 是**可以被同批其它请求的轮转立即回收**的；
用户/前端若拿这个 id 去 `/api/rtk/rollback`，会找不到目标（该端点不带 id 时恢复「全局最新」，
那可能是**另一次操作**的快照）。轮转没有排除「当前/在飞请求刚创建的备份」。

建议：轮转时跳过本请求创建的 id（以及正在使用中的 id），或把轮转放到请求结束之后；
`rollback` 对缺失 id 给出明确错误文案。

## 4.4 并发下的偶发 502（观察 1 次 / 30 次并发 toggle）—— 未能稳定复现

```
round1: [...5 个 200...] pi → 502
{"error":"Pi coding agent 的钩子文件形状未经验证，且 rtk CLI 失败：rtk 执行成功但目标状态未生效",
 "reason":"hook_cli_failed"}
后续 4 轮（每轮 6 个并发，共 24 次）全部 200。
```

只观察到一个样本，无法给出复现率；怀疑是多个 agent 并发调用同一个 rtk CLI（共享 HOME/rtk 自身状态）
时的相互干扰。建议蓝队用 `for i in 1..20` 循环压一轮确认。

## 4.5 次要：无 manifest 的孤儿目录不会被清理

```
$ mkdir /tmp/cac-r3/bk-G/zzz-orphan-no-manifest && touch .../junk
$ 触发一次 toggle（会跑 pruneRtkBackups）
$ ls /tmp/cac-r3/bk-G | grep -c orphan → 1（仍在）
```

`backupIds()` 只统计含 `manifest.json` 的目录，因此崩溃/中断留下的半成品目录会永久堆积
（也不会被 rollback 选中）。建议轮转时一并清理「无 manifest 且超过 1 天」的目录。
