## 3. 危险操作确认框的键盘行为 —— **缺陷（Escape 不可靠）**

同一页面、同一会话，连续 4 次「打开确认框 → 只按一次 Escape」：

```
escape trials: [{"i":0,"opened":true,"closedByOneEscape":false},
                {"i":1,"opened":true,"closedByOneEscape":false},
                {"i":2,"opened":true,"closedByOneEscape":false},
                {"i":3,"opened":true,"closedByOneEscape":false}]
```

另一次会话里观察到的相反表现（说明是竞态/焦点依赖，不是稳定可用）：

```
after click (modal open): {"overlays":8,"hasConfirmTitle":true,"focus":"确认操作将挂载 cursor 的 RTK 钩子到","focusInOverlay":true}
after Escape #1: {"overlays":2,"hasConfirmTitle":false,...}     ← 这一次一次就关掉了
```

还有一次：Tab 把焦点移到「取消」后按 Escape，**对话框不关**（`{"modal":true,"focusInModal":false}`），
只能鼠标点「取消」才关。

焦点陷阱本身是正常的（Tab 循环：容器 → 取消 → 确认执行 → 容器，焦点不出 modal）。
结论：**Escape 关闭不稳定**，与 Lead 在 `/keys` 的观测同源（TxModal 的 Escape 绑在遮罩上，是否命中取决于焦点/时序）。

截图：`03-after-escapes.png`、`04-modal-keyboard.png`、`05-escape-stuck.png`

## 4. 失败态展示 —— **缺陷（错误提示被随后的状态刷新清掉）**

点击「安装 rtk」→「确认执行」，接口固定 501（`/api/rtk/install` 实测 501 `local_install_not_supported`）。
用 20ms 间隔的 DOM 观察器可以看到提示出现后立即消失：

```
alert timeline: [{ "at": 1303, "text": "操作失败（未做任何静默降级） | HTTP 501 · 控制台不代为安装本机 rtk，请人工执行：curl -fsSL https://www.rtk-ai.app/install.sh | sh · 平面=local · 原因=local_install_not_supported" }]
alerts visible now: 0
API /api/rtk/install -> 501 {"error":"控制台不代为安装本机 rtk，请人工执行：curl -fsSL https://www.rtk-ai.app/install.sh | sh","plane":"local","reason":"local_install_not_supported"}
```

代码根因：`src/pages/RtkPage.vue:75-80` catch 里写 `errorText`，`finally` 里 `await load()`，
而 `load()` 成功时第 42 行 `errorText.value = ''` → 提示被自己清空；同页 `TxAlert`(第 102 行) 因此一闪而过。
影响面：**所有失败路径**（501 安装/升级、403 确认缺失、409 坏 JSON、503 rtk 缺失、远端 401/404）在 UI 上都表现为「点了没反应」。
