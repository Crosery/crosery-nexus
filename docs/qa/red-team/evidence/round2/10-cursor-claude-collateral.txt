# 缺陷1：cursor 开关的 claude 连带写入/残留（隔离实例 8795，临时 HOME=/tmp/cac-r2/home）
# 结论：cursor ON 会写 .claude/settings.json 但响应不报告；cursor OFF 不清理该连带；检测因此显示 claude=true

# 1) 干净基线：claude 无 rtk 条目，cursor 无 rtk 条目
$ node -e '...过滤掉 rtk 条目...' # 见 probe-local-writes.mjs 同目录
baseline: cursor_rtk=0 claude_rtk=0

# 2) POST /api/rtk/toggle {"agent":"cursor","on":true,"plane":"local","confirm":true}
HTTP 200  {ok:true, mechanism:"rtk-cli", backup:".../2026-10-01T00-47-28-287Z"}   ← 无 collateralRestored 字段
cli: {command:'rtk init -g --agent cursor --auto-patch', exitCode:0, stderr:'', ok:true}
AFTER cursor ON : cursor_rtk=1  claude_rtk=1        ← claude 被连带打开
changed files (.claude/CLAUDE.md, .claude/RTK.md 新建；.claude/settings.json 改动)：
  > .claude/CLAUDE.md
  > .claude/RTK.md
  < .claude/settings.json
  > .claude/settings.json

# 3) POST /api/rtk/toggle {"agent":"cursor","on":false,...}
HTTP 200  {ok:true}                                ← 仍然没有 collateralRestored
AFTER cursor OFF: cursor_rtk=0  claude_rtk=1        ← claude 的 rtk 钩子留在原地
status: claude=true cursor=false

# 4) 残留文件（cursor OFF 之后仍在）
~/.claude/RTK.md      EXISTS  (首行 '# Command output'，rtk 生成)
~/.claude/CLAUDE.md   EXISTS

# 5) 代码根因
server/rtkService.ts:631-645 repairCollateral() 只在 isAgentOn(owner,before) && !isAgentOn(owner,after) 时恢复，
  即只处理「原本开着、被连带关掉」；对「原本关着、被连带打开」不处理。
src/pages/RtkPage.vue:57 只在 result.collateralRestored 非空时提示，ON 方向没有可提示字段。
# 反向（claude OFF → cursor 被连带关闭）实测是有修复的：
claude OFF response: {"ok":true,"collateralRestored":["cursor"]}  cursor_rtk=1（保留）
